# Ticketo (BookMyShow Clone) - Project Progress Log

## High-Level Design & Context
- **Project Goal:** Ticket booking app for placements (Intermediate to Advanced level).
- **Current Phase:** Building the backend first.
- **Architecture:** Microservices architecture.
- **Current Services:**
  - `api-gateway`: Routes traffic to the correct microservice (`/api/auth`, `/api/movies`, `/api/shows`, `/api/bookings`).
  - `user-service`: Handles user authentication and management.
  - `movie-service`: Manages movies, theatres, shows, and seats.
  - `booking-service`: Handles the booking flow (currently synchronous).

## Progress
**Completed (Phase 1):**
- [x] API Gateway setup
- [x] User Service setup
- [x] Movie Service setup
- [x] Booking Service setup

**Completed (Phase 2):**
- [x] Redis-based API Rate Limiting in `api-gateway`
- [x] Redis Cache-Aside in `movie-service` (movies list + show details)
- [x] Redis Distributed Seat Locking in `booking-service` (SET NX EX, prevents double-booking)
- [x] Cache invalidation on write (SCAN-based, non-blocking)

**Completed (Phase 3):**
- [x] Kafka + Zookeeper added to `docker-compose.yml`
- [x] `payment-service` created (DB, mock processor, Kafka worker)
- [x] `notification-service` created (pure Kafka worker, no HTTP)
- [x] `booking-service` refactored to async Kafka flow
  - Publishes `booking-initiated` event immediately after creating PENDING booking
  - Kafka consumer handles `payment-success` (confirm seats + notify) and `payment-failed` (rollback)
- [x] Shared Kafka utilities created (`shared/kafka/kafkaClient.js`, `producer.js`, `consumer.js`)

**Completed (Phase 4):**
- [x] **Frontend:** React + Vite SPA built with Tailwind CSS.
  - Features: Glassmorphism design, premium dark UI, subtle micro-animations.
  - Pages: Home (Movie Catalog), Movie Details (Shows), Seat Selection (Booking).
  - Auth: JWT integrated with Login/Register pages.
  - Asynchronous UI: Booking Status page added that polls `/bookings/:id` while Kafka processes the payment in the background.

## 📁 Monorepo Layout

```
cineflow/
│
├── docker-compose.yml              ← Spins up ALL services + Postgres + Redis + Kafka
├── .env.example                    ← Template for environment variables
├── README.md
│
├── services/
│   ├── api-gateway/                ← Entry point for all client requests
│   ├── user-service/               ← Auth, Register, Login
│   ├── movie-service/              ← Movies, Theatres, Shows, Seats
│   ├── booking-service/            ← Seat lock, create booking
│   ├── payment-service/            ← Mock payment processing
│   └── notification-service/       ← Email/SMS after booking
│
├── frontend/                       ← React + Tailwind CSS
│
└── shared/                         ← Shared utilities (reused across services)
    ├── kafka/                      ← Kafka producer/consumer helpers
    ├── redis/                      ← Redis client setup
    └── middleware/                 ← JWT verification middleware
```

## 📁 Each Service — Same Structure (Consistent Pattern)

Every service follows this exact same layout — makes it easy to explain and navigate.

```
services/user-service/
│
├── src/
│   ├── config/
│   │   └── db.js                   ← PostgreSQL connection (pg / Sequelize)
│   │
│   ├── controllers/
│   │   └── user.controller.js      ← req → res logic (thin layer)
│   │
│   ├── routes/
│   │   └── user.routes.js          ← Express route definitions
│   │
│   ├── services/
│   │   └── user.service.js         ← Business logic lives here
│   │
│   ├── models/
│   │   └── user.model.js           ← Sequelize/Prisma model (DB schema)
│   │
│   ├── middleware/
│   │   └── auth.middleware.js      ← JWT check (only in services that need it)
│   │
│   └── app.js                      ← Express app setup
│
├── .env                            ← PORT, DB_URL, JWT_SECRET etc.
├── package.json
├── Dockerfile
└── index.js                        ← Entry point (starts server)
```

> Same pattern for **movie-service**, **booking-service**, **payment-service**, **notification-service** — just different controllers/models.
